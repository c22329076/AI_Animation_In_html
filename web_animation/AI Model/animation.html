1. 什麼是 Vibe Coding?

"我只負責寫 Prompt，複製貼上程式碼，執行，報錯，把錯誤扔回給 AI。我不再寫具體的語法，我只管理程式設計的'氛圍' (Vibe)。"

— Andrej Karpathy (前 Tesla AI 總監, OpenAI 創始成員)

核心概念

  • 從 Coder 到 Manager： 你不再是搬磚的工人，你是包工頭。
  • 自然語言即程式碼： 英語（或中文）成為了新的程式語言。
  • 關注點轉移： 從“這個函式怎麼寫”轉移到“這個功能應該長什麼樣”。
  • 只要能跑就行： 即使程式碼很醜，只要透過測試且實現功能，就是好程式碼。
// 傳統程式設計
function qSort(arr) { ... }

// Vibe Coding
"幫我寫一個快速排序，要帶視覺化動畫，用 React 實現。"

技術演進歷程

1. Manual Coding
查檔案，手寫每一行程式碼，StackOverflow 複製貼上。
2. Copilot Era (AI 輔助)
Tab 鍵補全程式碼，AI 是副駕駛，依然需要人懂每一行邏輯。
3. Vibe Coding (AI 主導)
Composer/Agent 模式。AI 編寫整個檔案/模組，人類負責稽核和引導。

2. 主流開發工具

工欲善其事，必先利其器。

Cursor 行業標杆

  • 核心功能： Tab 自動補全 (Copilot++)、Composer (多檔案編輯)、Codebase Indexing (全庫理解)。
  • 優勢： 體驗最流暢，模型選擇多 (Claude 3.5, GPT-4o)，社群外掛豐富。
  • 適用場景： 所有型別的全棧開發。

Trae 位元組跳動出品

  • 核心功能： 類似 Cursor，但不僅是 IDE，更強調 Agent (Solo 模式)。它可以自主執行終端命令、建立檔案。
  • 優勢： 免費 (目前)，中文支援極其友好，國內訪問速度快。
  • 評價： "Cursor 的最強國產平替，且在 Agent 能力上更進一步。"

AWS Kiro 規範驅動

注：可能為您提到的 "Kiro"。

  • 核心理念： Spec-Driven Development (規範驅動開發)。
  • 功能： 不僅僅是寫程式碼，它會先生成需求檔案 (Spec)，確認無誤後再生成程式碼。
  • 特色： "Hooks" 功能，自動在儲存時更新檔案或執行測試。
  • 適用： 需要嚴格檔案和流程的企業級專案。

3. 常用命令列 (CLI) 程式設計

拋棄滑鼠，用自然語言控制終端。

代表工具：Claude Code / Codex

$ claude "幫我檢查一下當前目錄的 git status，如果有修改，提交併推送到 origin main，提交資訊寫 'update features'"

工作原理：

  1. 使用者輸入自然語言指令。
  2. LLM 將其翻譯為 Shell 命令 (git add ., git commit -m ...)。
  3. 工具展示即將執行的命令。
  4. 使用者確認 (Y/n) -> 執行。

效率提升點

  • 自動化流程： "把 src 目錄下所有 .js 檔案轉為 .ts，並修復型別錯誤。" (一行命令代替半天工作)
  • 環境配置： "幫我配置一個 Dockerfile，基於 Node 18，暴露 3000 連接埠。"
  • Debug： 直接將錯誤日誌管道傳輸給 AI：
    npm run build 2>&1 | claude "解釋這個錯誤並給出修復方案"

4. 什麼是 MCP?

Model Context Protocol

AI 時代的 USB 介面標準

背景與起源

以前，如果你想讓 ChatGPT 讀取你的本地資料庫，你需要寫一大堆程式碼來“喂”給它。每個工具（Linear, GitHub, Slack, Postgres）都需要單獨的介面卡。

Anthropic 提出了 MCP 標準：
讓所有資料來源都變成統一的“插頭”，所有 AI 模型都變成統一的“插座”。

架構與案例

MCP Host (Cursor/Claude)
⬇️⬆️
MCP Server (GitHub/SQLite)
應用案例：
你在 Cursor 裡問："查看我上週在 Linear 上分配的任務，並在程式碼裡找到對應的 TODO 註釋。"

Cursor 透過 MCP 協議連線 Linear 獲取資料，不需要把資料手動複製貼上。

5. 什麼是 Agent (智慧體)?

從“聊天機器人”進化為“數字員工”

核心概念：迴圈 (Loop)

感知 (Perception) → 思考 (Brain) → 行動 (Action) → 觀察結果 (Observation) → 感知...

Chatbot: 你問它答，它沒有手腳。
Agent: 你給目標，它自己分析，自己呼叫工具，自己改錯，直到完成。

實際案例

場景： 修復一個 Bug。
Agent 的思考過程：
  1. [思考] 使用者說登入報錯，我要先復現。
  2. [行動] 執行 `npm test login`。
  3. [觀察] 測試失敗，報錯 "500 Internal Server Error"。
  4. [思考] 可能是後端介面掛了，我要檢查 `auth.js`。
  5. [行動] 讀取 `auth.js` 原始碼。
  6. [思考] 發現漏了一個 await。
  7. [行動] 修改程式碼，儲存。
  8. [行動] 再次執行測試... 透過！

6. 什麼是 Skills?

賦予 Agent “手”和“腳”

含義與演變

定義： Skills (或 Tools) 是封裝好的函式，Agent 知道如何呼叫它們。

{
  "name": "send_email",
  "description": "Send an email to a user",
  "parameters": { "to": "string", "body": "string" }
}

演變： 從簡單的計算器工具，到現在可以操作瀏覽器 (Puppeteer)、運算元據庫、部署雲服務。

應用效果

  • 提升能力： 原本 LLM 不知道當前時間，有了 `get_time` skill 就能知道了。
  • 最佳化流程：
    給 Agent 一個 `deploy_to_vercel` 的 Skill。
    指令："寫完程式碼後自動幫我部署上線。"
    結果：程式碼寫完 -> 測試透過 -> 自動呼叫部署 API 介面 -> 回到上線 URL。

7. 綜合案例：從零構建番茄鍾

Vibe Coding 全流程演示

Step 1: 前端 UI 設計 (Vibe 模式)

Prompt:
"用 React + Tailwind CSS 幫我寫一個現代極簡風格的番茄鍾。背景要是深色的，中間一個大大的倒計時，下面有開始、暫停、重置按鈕。字型要用等寬字型。"

操作：
在 Cursor Composer 中輸入 -> 接受所有程式碼 -> 預覽。

25:00

Step 2: 核心功能與 Agent 除錯

需求： "點擊開始後倒計時，結束時播放一段提示音。"

遇到 Bug： 點擊暫停後再開始，時間跳動異常（倒計時加速了）。

Vibe Debugging： 不要自己去查 `useEffect` 依賴。直接把 Bug 現象告訴 Trae/Cursor：
"點擊暫停再開始，計時器速度變快了，好像是有多個 setInterval 在執行，幫我修復它。"

Agent 行動： 自動定位到 `useEffect` 清理函式缺失，新增 `clearInterval`，問題解決。

Step 3: 部署與維護

利用 CLI / Skills：

@Terminal 幫我打包這個專案 (npm run build)
@Terminal 檢查 build 資料夾大小，如果超過 1MB 給我報警。
@Agent 使用 Vercel CLI 部署當前專案，並將生產環境 URL 存到 README 中。
🎉 專案上線完成！全程未手動編寫一行 HTML/CSS。

總結

  • Vibe Coding 是心態的轉變：敢於放手讓 AI 寫程式碼。
  • 工具 (Cursor/Trae) 是你的外骨骼機甲。
  • MCP & Skills 是連線世界的橋樑。
  • Agent 是你未來的數字同事。

擁抱變化，成為 AI 的指揮官！
